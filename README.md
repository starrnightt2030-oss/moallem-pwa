# منصّة المعلّم — نظام إدارة الدروس والطلاب

تطبيق ويب احترافي بنظام **PWA** لإدارة التدريس الخصوصي: الطلاب، المواد، المجموعات،
الحصص، الحضور والغياب، الحسابات والمدفوعات، المصروفات الإضافية، مشاريع التخرج،
الرسائل والملفات، والتقارير المالية.

عربي بالكامل · RTL · Mobile First · وضع ليلي · يعمل كتطبيق مثبَّت على Android وسطح المكتب.

---

## 1. التقنيات المستخدمة ولماذا

| الطبقة | الاختيار | السبب |
|---|---|---|
| الواجهة | **React 19 + Vite + TypeScript** | أسرع بناء، حجم صغير، تقسيم تلقائي للحزم |
| التصميم | **Tailwind CSS v4** + مكوّنات مبنية على **Radix UI** | نظام تصميم موحّد، وصولية جاهزة، دعم RTL كامل |
| الأيقونات | **Lucide** | مكتبة احترافية خفيفة (لا إيموجي في عناصر الواجهة) |
| الخط | **Cairo** | خط عربي حديث وواضح على كل الشاشات |
| قاعدة البيانات | **Supabase (PostgreSQL)** | SQL حقيقي + علاقات + معاملات + **Row Level Security** |
| المصادقة | **Supabase Auth** | كلمات مرور مُشفَّرة، توكنات JWT، لا تخزين مكشوف |
| التخزين | **Supabase Storage** | حاوية خاصة + روابط موقّعة مؤقتة |
| دوال الخادم | **Vercel Serverless** | لإدارة حسابات الطلاب بمفتاح الخدمة (لا يصل للمتصفح) |
| الاستضافة | **Vercel** | مجاني، HTTPS تلقائي (شرط أساسي للـ PWA) |

**التكلفة: صفر.** كل ما سبق ضمن الخطط المجانية، وهي أكثر من كافية لـ 150–200 طالب.
(تفاصيل الحدود في القسم 8.)

## 3. إعداد Supabase (خطوة بخطوة)

### 3.1 إنشاء المشروع
1. ادخل على <https://supabase.com/dashboard> وأنشئ حسابًا مجانيًا.
2. **New Project** → اختر اسمًا وكلمة مرور لقاعدة البيانات، واختر أقرب منطقة (مثلًا Frankfurt).

### 3.2 تشغيل ملفات SQL
من **SQL Editor** شغّل الملفات بهذا الترتيب (انسخ محتوى كل ملف ثم Run):

1. `supabase/01_schema.sql` — الجداول والعلاقات والفهارس
2. `supabase/02_functions.sql` — الدوال والمشغّلات (الدورات، المدفوعات، الرسائل)
3. `supabase/03_policies.sql` — سياسات الأمان RLS + حاويات التخزين
4. `supabase/04_seed.sql` — *(اختياري)* سنوات ومجموعات ومواد تجريبية

### 3.3 إيقاف التسجيل الذاتي (مهم للأمان)
**Authentication → Providers → Email** → أوقف **Enable Sign Ups**.
هذا يمنع أي شخص من إنشاء حساب بنفسه؛ أنت وحدك من ينشئ حسابات الطلاب.

### 3.4 إنشاء حساب المدرّس
**Authentication → Users → Add user** → أدخل بريدك وكلمة مرور قوية، وفعّل *Auto Confirm*.

> أول مستخدم في النظام يصبح **مديرًا** تلقائيًا.
> لو احتجت ترقية حساب لاحقًا، شغّل في SQL Editor:
> ```sql
> select public.make_admin('your@email.com');
> ```

### 3.5 نسخ المفاتيح
**Project Settings → API** وانسخ:
- `Project URL`
- `anon public key`
- `service_role key` ← **سرّي، للخادم فقط**

## 4. متغيرات البيئة

```env
# للمتصفح (آمنة للنشر — محميّة بسياسات RLS)
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
VITE_STUDENT_EMAIL_DOMAIN=students.moallem.app

# للخادم فقط — لا تضعها أبدًا في متغير يبدأ بـ VITE_
SUPABASE_URL=https://xxxx.supabase.co
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOi...
STUDENT_EMAIL_DOMAIN=students.moallem.app
```

`STUDENT_EMAIL_DOMAIN` نطاق وهمي داخلي فقط — يُبنى منه بريد دخول الطالب
(`st-2026-001@students.moallem.app`). الطالب لا يراه ولا يحتاجه؛ هو يدخل بكوده ورمزه السري.

## 5. النشر على Vercel

1. ارفع المشروع على GitHub.
2. <https://vercel.com> → **Add New → Project** → اختر المستودع.
3. الإعدادات تُكتشف تلقائيًا (Framework: Vite · Build: `npm run build` · Output: `dist`).
4. أضف **كل** متغيرات البيئة الستّة أعلاه في **Environment Variables**.
5. **Deploy**.

بعد النشر:
- افتح الرابط من كروم على الأندرويد → **⋮ → تثبيت التطبيق**.
- على سطح المكتب → أيقونة التثبيت في شريط العنوان.

> إن أردت النشر على Cloudflare Pages أو Netlify بدلًا من Vercel، فستحتاج نقل
> `api/students-account.ts` إلى صيغة دوالها (Workers / Netlify Functions) — الباقي يعمل كما هو.

## 6. أول تشغيل — الترتيب الموصى به

1. **الإعدادات → التطبيق**: اسم التطبيق، اسمك، بيانات التواصل.
2. **الإعدادات → الهوية البصرية**: الشعار والألوان.
3. **السنوات والمجموعات**: أضف السنوات (الصف الأول/الثاني/الثالث) ثم المجموعات.
4. **المواد**: كل مادة بسعرها المستقل وعدد حصص دورتها (الافتراضي 4).
5. **الطلاب**: أضف الطالب وسجّله في مواده (يُحسب إجمالي الدورة تلقائيًا).
6. **جدول الحصص**: أنشئ الحصص — يمكن توليد 4 أو 8 أسابيع دفعة واحدة.
7. **الحضور**: اختر الحصة → «الجميع حاضر» → عدّل الغائبين → حفظ.
8. من ملف الطالب: **إنشاء حساب** لإعطائه كوده ورمزه السري.

## 7. كيف يعمل نظام الدورات (الأربع حصص)

- الدورة = عدد الحصص المحدّد للمادة (افتراضيًا **4**).
- **تُحتسب الحصص المنفّذة فعليًا فقط** — أي التي حالتها «تم تنفيذها».
- الحصة التي **تؤجّلها أو تلغيها أنت لا تُحتسب على الطالب إطلاقًا**، حتى تُنفَّذ فعليًا.
- عند بدء دورة جديدة يُنشأ مستحق ماليّ تلقائيًا بسعر المادة لهذا الطالب
  (أو سعره الخاص إن حُدّد له سعر مختلف).
- إن لم يدفع الطالب دورة سابقة، يظل المبلغ القديم مستحقًا ويُضاف إليه الجديد.
- **قابل للتخصيص** من الإعدادات → الحضور:
  - هل يُحتسب **الغياب** ضمن حصص الدورة؟ (افتراضيًا نعم)
  - هل يُنشأ المستحق عند **بداية** الدورة أم عند **اكتمالها**؟ (افتراضيًا البداية)
- الحساب **يُعاد اشتقاقه من السجل بالكامل** عند أي تعديل، فلا تتراكم أخطاء
  لو صحّحت حضورًا قديمًا أو غيّرت حالة حصة.

## 8. الحدود المجانية وما يجب الانتباه له

| الخدمة | الحد المجاني | استهلاكك المتوقع (200 طالب) |
|---|---|---|
| Supabase — قاعدة البيانات | 500 ميجابايت | أقل من 50 ميجابايت |
| Supabase — التخزين | 1 جيجابايت | حسب الملفات المرفوعة ← **النقطة الوحيدة التي قد تمتلئ** |
| Supabase — النطاق الشهري | 5 جيجابايت | كافٍ |
| Supabase — المستخدمون | 50,000 شهريًا | 200 |
| Vercel | 100 جيجابايت نطاق | كافٍ جدًا |

**تنبيه واحد فقط:** مشروع Supabase المجاني **يُوقَف مؤقتًا بعد 7 أيام من عدم النشاط**
(يعود بضغطة زر من لوحة التحكم). الاستخدام اليومي العادي يمنع ذلك تمامًا.

**لتقليل الاستهلاك:** الحد الأقصى للملف 20 ميجابايت (يمكن تعديله في `FilesPage.tsx`)،
واضغط الصور قبل الرفع، واحذف الملفات القديمة من صفحة الملفات.

## 9. الأمان — ما هو مطبَّق فعليًا

- **Row Level Security على كل جدول.** الصلاحيات في قاعدة البيانات نفسها،
  لا في الواجهة — الطالب لا يستطيع قراءة بيانات طالب آخر حتى لو نادى الـ API مباشرة.
- **الطالب للقراءة فقط.** لا توجد أي سياسة `INSERT/UPDATE/DELETE` له
  عدا وضع علامة «مقروء» على رسائله وإشعاراته.
- **الرسائل مُستهدَفة من قاعدة البيانات**: رسالة لمجموعة 1 لا يقرؤها غيرها إطلاقًا.
- **مفتاح الخدمة على الخادم فقط**، ودالة الحسابات تتحقق من أن المنادي مدير قبل أي عملية.
- **الملفات في حاوية خاصة**، تُفتح بروابط موقّعة تنتهي بعد ساعة.
- **السجلات المالية لا تُحذف نهائيًا** — تُلغى (Soft Delete) مع بقاء الأثر.
- **سجل عمليات (Audit Log)** للعمليات الحساسة: المدفوعات، المستحقات، الحضور، الحسابات.
- كل الاستعلامات عبر عميل Supabase المُعامَل (Parameterized) → **لا حقن SQL**.
- React يهرّب المخرجات تلقائيًا → **لا XSS**.

## 12. أسئلة سريعة

**كيف يدخل الطالب؟** من نفس رابط التطبيق → تبويب «طالب» → كوده + الرمز السري الذي أعطيته له.

**نسيت رمز طالب؟** ملف الطالب → إجراءات سريعة → تغيير الرمز.

**أريد إخفاء الأرصدة أمام شخص؟** زر العين 👁 في الشريط العلوي — يخفي كل المبالغ فورًا.

**غيّرت سعر مادة، ماذا عن المستحقات القديمة؟** تبقى كما هي (سجل تاريخي صحيح)،
والسعر الجديد يُطبَّق على الدورات القادمة.

**تعديل سعر لطالب واحد؟** من نموذج الطالب: فعّل المادة واكتب سعرًا خاصًا في خانة السعر.

## 13. التحقق من صحة النظام

قبل التسليم تم تشغيل ملفات SQL كاملة على PostgreSQL 16 واختبار المنطق فعليًا:

| الاختبار | النتيجة |
|---|---|
| تنفيذ الملفات الأربعة بدون أخطاء | ✅ |
| 5 حصص (4 منفّذة + 1 مؤجّلة) → الدورة 4/4 والمؤجّلة **لم تُحتسب** | ✅ |
| فتح دورة ثانية تلقائيًا + إنشاء مستحقها | ✅ |
| تراكم القديم مع الجديد (500 + 500 = 1000) | ✅ |
| توزيع الدفعة على الأقدم أولًا (700 → دورة 1 كاملة + 200 من دورة 2) | ✅ |
| بند جماعي لمجموعة → مستحق + إشعار لكل طالب فيها | ✅ |
| توليد كود الطالب تلقائيًا (ST-2026-001) | ✅ |
| الطالب يرى نفسه فقط (1 من 2) ومستحقاته فقط | ✅ |
| الطالب لا يستطيع تعديل بياناته (0 صفوف متأثرة) | ✅ |
| الطالب لا يستطيع إدراج دفعة (رُفض بـ RLS) | ✅ |
| الطالب لا يستطيع استدعاء دوال الإدارة (رُفض: غير مصرّح) | ✅ |
| سجل العمليات غير مرئي للطالب (0) | ✅ |
| رسالة لمجموعة 1: يراها أحمد (1) ولا تراها سارة (0) | ✅ |
| الزائر غير المسجّل: يرى الهوية البصرية فقط، و0 من كل الجداول | ✅ |

## 14. حدود النسخة الحالية (بوضوح)

- **العمل بدون إنترنت جزئي**: التطبيق يفتح ويعرض آخر بيانات محمّلة من الكاش،
  لكن **العمليات الحساسة** (تسجيل دفعة، حفظ حضور، حذف) تحتاج اتصالًا،
  ولا تُعتبر محفوظة إلا بعد نجاحها فعليًا على الخادم. لا يوجد طابور مزامنة offline.
- **إشعارات Web Push** (خارج التطبيق) غير مفعّلة — الإشعارات داخل التطبيق فقط،
  وهي تعمل بالكامل. يمكن إضافة Push لاحقًا عبر Supabase Edge Functions + VAPID.
- **ملفات الطالب** تصل إليه مرفقة بالرسائل (وهي الطريقة التي تضمن أن يرى
  ما أُرسل له أو لمجموعته فقط) وليست في تبويب منفصل.
- **بطاقات لوحة المعلومات** ثابتة الترتيب حاليًا؛ البنية تسمح بإضافة السحب
  وإعادة الترتيب لاحقًا دون تغيير قاعدة البيانات.
- **الواجهة عربية فقط** حاليًا، لكن كل النصوص في ملفات المكوّنات ويمكن
  استخراجها لملف ترجمة وإضافة الإنجليزية دون إعادة بناء الواجهة.
